## How decisions are made

- **Routine fixes and documentation** merge when CI is green and the change matches [CONTRIBUTING.md](../.github/CONTRIBUTING.md).
- **Behaviour, security or architecture changes** need an issue or pull-request discussion first when the impact is not
  obvious from the diff.
- **Disputes** under the [Code of Conduct](../.github/CODE_OF_CONDUCT.md) are handled by the maintainer; there is no separate
  governance council.

## Becoming a contributor

Anyone can open issues and pull requests. Read [CONTRIBUTING.md](../.github/CONTRIBUTING.md) and run the same checks CI runs. Code
owners are not solicited on a schedule; sustained, high-quality contributions may lead to triage or commit access at
the maintainer's discretion.

## Response expectations

Issues and pull requests are handled when time allows. There is no guaranteed response time. Security reports per
[SECURITY.md](../.github/SECURITY.md) are prioritised. If an issue has no activity from a maintainer for a long period, it may be
closed as stale; you can reopen with new information.

## Contact

Use GitHub Issues for bugs and features ([SUPPORT.md](../.github/SUPPORT.md)). Do not e-mail the maintainer for routine support.
